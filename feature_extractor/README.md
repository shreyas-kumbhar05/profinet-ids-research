# Feature Extractor — PROFINET RT Feature Engineering

## Purpose

The feature extractor converts raw PROFINET RT packet captures into
structured feature data for analysis and later ML experiments.

It reads pcap captures and produces feature data in CSV format and
SQLite format.

Input:
- pcap captures from `traffic_generator/` (Week 4)
- attack captures from `attacks/` (Week 6 onward)

Output:
- `sample_features.csv`
- `features.db`

---

## Quick Start

Extract features from a capture:

```bash
python3 feature_extractor/extractor.py \
  --pcap traffic_generator/captures/sample_normal.pcap
```

Custom output paths:

```bash
python3 feature_extractor/extractor.py \
  --pcap path/to/capture.pcap \
  --csv output_features.csv \
  --db output_features.db
```

The extractor filters the capture for PROFINET RT traffic using
EtherType `0x8892`.

## Features Extracted

| Feature | Representation | Description |
|---|---|---|
| Inter-arrival time | `iat` | Time in seconds between consecutive PROFINET RT frames |
| Frame size | `frame_size` | Total Ethernet frame length in bytes |
| Source MAC consistency | `src_mac_known` | Whether the source MAC matches the established baseline MAC |
| Payload entropy | `payload_entropy` | Shannon entropy of the extracted IO payload in bits/byte |
| EtherType distribution | Session-level | Distribution of observed Ethernet EtherTypes |

The first four features are stored as per-frame rows in the CSV and
SQLite `features` table.

EtherType distribution is calculated as a session-level statistic
because it describes the capture as a whole rather than an individual
frame.

See `feature_definitions.md` for the calculation details and detection
rationale.

## Output Structure

### CSV — `sample_features.csv`

The CSV contains one row for each frame after IAT alignment.

The first captured frame does not produce an IAT because there is no
previous timestamp, so the number of feature rows is one less than the
number of captured frames.

Example:

```text
iat,frame_size,src_mac_known,payload_entropy
0.004012,60,True,0.0
0.003998,60,True,0.0
0.004105,60,True,0.0
```

### SQLite — `features.db`

The database contains two tables:

- `features` — per-frame feature data plus `session_id`
- `sessions` — metadata for each extraction run

Example query:

```python
import sqlite3
import pandas as pd

conn = sqlite3.connect("feature_extractor/features.db")

df = pd.read_sql(
    "SELECT * FROM features WHERE session_id = 'abc123'",
    conn
)

conn.close()
```

## Baseline Statistics

The current baseline was generated from a 30-minute PROFINET RT capture
using the Week 4 traffic generator with a configured 4 ms cycle time and
0.3 ms Gaussian jitter.

### Dataset

- Captured PROFINET packets: 449,913
- Feature rows: 449,912

### Observed baseline

| Feature | Mean | Std Dev / Observation |
|---|---:|---:|
| IAT | 4.000 ms | 4.118 ms |
| Frame size | 59.999991 bytes | 0.005963 bytes |
| Source MAC consistency | 100% known | — |
| Payload entropy | 0.0 bits/byte | 0.0 |
| EtherType | 0x8892 | 100% |

Almost every frame was 60 bytes. One 56-byte frame was observed at the
end of the capture and was retained in the dataset.

The IAT mean closely matches the intended 4 ms cycle time, while the
measured standard deviation is substantially higher than the configured
0.3 ms. The same timing behaviour was observed during Week 4 and is
associated with sporadic scheduling delays in the VirtualBox execution
environment.

See `baseline_analysis.md` for the full statistical analysis.

## Current Scope

The current extractor is designed around the controlled PROFINET RT
traffic generated by this project.

The baseline represents the behaviour of the current simulation and
should not be treated as a universal statistical definition of all
PROFINET deployments.

The extracted features will be used in Week 6 to compare normal traffic
against controlled attack scenarios.
